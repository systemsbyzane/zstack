# Cortex assignment protocol

Use [clear task communication](communication.md) for all human-readable briefs and reports. Keep machine identifiers and ledgers in metadata/trackers; they supplement, rather than replace, readable instructions.

Resolve actual thread/project/environment IDs and links through supported tools. The chief alone owns its atomic state and sanitized projection. Record assignment identity, coordinator link/workspace, outcome, phase order, authority/exclusions, ownership, evidence, decisions, and delivery receipts; exclude secrets. Each assignment has one current instruction record: effective authority, next outcome, owner, and any active hold with a release condition. Mark replaced instructions superseded; a late event must not revive them.

An assigned task authorizes creating its separate coordinator thread in this workflow. Launch through supported T3 workspace binding with the complete assignment and return destination. After uncertain delivery, reconcile existing threads/receipts before retrying; do not duplicate assignments or invent bindings. Follow the host's launch/read/wait requirements and exact-link rules.

The envelope contains: user outcome and ordered phases; acceptance and deliverables; chief identity/return link; actual project/workspace/base; existing authority and restrictions; preferred/required models if any; ownership and known runtime facts. It grants ordinary necessary execution within that task, not unrelated merges/deployments or security changes. Use Luna for worker execution when available and appropriate unless the user requests another model; choose escalation for concrete task needs and disclose it. No fixed hour allowance or recurring permission checkpoint is implied.

Coordinators delegate product implementation and own scoping, integration, review, verification, and delivery. They may make small fixes for their own review findings. Routine setup, fixture, command, and formatting recovery stays with the current owner. Quiet read-only check-ins use existing output at natural boundaries; no worker polling, interrupts, timers, or watcher agents. Return only meaningful user milestones, integrated delivery, material dependency changes, or genuine authority/decision/private-authentication blockers. Filter internal chatter rather than forwarding routine events.

Use stable assignment/event/delivery IDs. A material event includes reported UTC, assignment/coordinator identity and exact link, status/phase, concise result, tested revision, actual checks, evidence paths, limits, and a real decision if needed. Verify sender provenance against the roster before adopting reports; claimed IDs alone are insufficient. Deduplicate events, preserve earlier evidence, and distinguish last-reported state from live execution. A worker exit is not completion.

The chief sends feedback once to the owning coordinator and records the receipt. Existing user authority persists. Coordinator discretion handles routine recovery and integration; arbitrary time/cycle targets do not require renewal. Explicit user hard limits, scope restrictions, private authentication, and consequential decisions still govern. On repeated failure, change the approach or ownership decisively rather than serially renewing the same task. No polling/watchdogs; follow completion wakes.

Ready means the requested integrated outcome has been verified and deliverables exist. Report real media/measurements and material limitations; do not fabricate migrated files, executed checks, or provider access. User acceptance does not imply an unrequested merge or deployment.
