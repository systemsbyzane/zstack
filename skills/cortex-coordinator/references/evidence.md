# Verification and handoff evidence

The coordinator owns integrated verification and may execute it directly or through a suitable worker. Keep the runtime owner and verified environment through the phase; do not hand setup repeatedly between short-lived workers.

Run checks that assess the requested behavior: focused automated tests or evaluation runners when appropriate, necessary compilation, real provider integration where requested, and actual UI/persistence checks. Respect explicit task-specific testing preferences. A synthetic response is not a provider result; an inferred stage is not a directly captured stage. Compare baseline and candidate with identified source/configuration and preserve failed outcomes in denominators.

For UI work, exercise the actual affected journey and reload/persistence when required. Capture real screenshots and video when requested or necessary to demonstrate the change. Do not use mockups or a blocked-form video as proof of a completed workflow. Keep media outside published product code unless requested, redact secrets, and use current host rendering/file-link rules. Verify a preview before claiming it is available.

For backend/AI work, report measured quantities, units, sample sizes, cohort selection, provider/runtime identity, failures, uncertainty, and limits. Preserve exact quantities and source citations. Private gold/holdout separation applies when the assignment requires it. Do not invent composite accuracy or generalize one example to the whole cohort.

Return the concrete result, PR/artifacts, what was verified, actual evidence, and material limits to Cortex. Missing required evidence means partial, not complete. User review follows completed authorized work; do not ask the user to perform the required verification for the coordinator.
